# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Blog rendering decisions live in `docs/adr/0003-blog-infrastructure.md`; body component/style hooks live in `src/alberto_codes_site/pages/blog.py`. Browser scrollbar verification is documented in `docs/validation/site-pre-overflow/README.md`.
- Check `.github/workflows/deploy.yml` before waiting for pull-request CI: deployment runs on pushes to main, not pull requests.
- Convention: a post about a tagged release closes with one link to that release's GitHub page — the post's own tag only, not every inline mention, an earlier tag it references, or a later one. Copy the shape from the closing bullet of `src/posts/2026-09-02-googles-4-bit-gemma-already-fit-my-card.md`, and write the descriptive clause from what that tag actually carries. This holds for vramfit posts as well as saucier ones; a post counts as being about a release when that release's own notes name it as the headline writeup. The release notes already link back to the post, so the post side is the half that gets forgotten.
- Product-facing counts on the projects and home pages are hand-copied from other repositories, and a static build cannot re-read them. The comment above `PROJECTS` in `src/alberto_codes_site/pages/projects.py` names the file or command behind each figure and which ones have no source; refresh from there rather than from anything already on the site.
- Convention: a LinkedIn post for a blog post is written for a general professional reader, not for someone who already knows the domain. The shape the captain accepted on 2026-09-05, in order: one plain sentence naming the concrete thing built, with no domain vocabulary in it; a second line that turns it, saying what is surprising or counterintuitive; one worked example small enough to hold in the head; the AI failure mode named flatly, in the reader's terms rather than the project's; the domain nouns translated out entirely; a close that generalises to the reader's own world rather than to the project; then the bare post URL, alone on the last line. Two rejected drafts define the anti-patterns. One was accurate and unreadable — factually correct but written in the source material's own vocabulary throughout, which reads as expertise to the author and as noise to everyone else. The other led with the writer's own war story from making the thing: lead with what the post achieves, never with what it cost to build. Read `src/posts/2026-09-05-the-parent-finally-has-a-verb.md` next to the accepted LinkedIn text (not committed here) to see the same content at both registers.
- Format for those LinkedIn posts, non-negotiable because the captain pastes from a phone into the LinkedIn mobile app and cannot fix anything afterwards: plain text only, no markdown of any kind — no asterisks, underscores, hash headings, backticks, tables, or `[text](url)` links — with bare URLs written out in full, deliberate line breaks, and short paragraphs. LinkedIn truncates around 210 characters, so the first two lines must earn the click on their own. Offer exactly one final version, never a menu.

## Maintaining this file

Keep this file for knowledge useful to almost every future agent session in this project.
Do not repeat what the codebase already shows; point to the authoritative file or command instead.
Prefer rewriting or pruning existing entries over appending new ones.
When updating this file, preserve this bar for all agents and keep entries concise.
